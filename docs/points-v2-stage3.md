# Points v2.0 Stage 3: fixture integration and production handoff

## Current scope

This branch adds an **inactive** schema-v2 development preview. The production site continues to use the existing v1 Apps Script endpoint, validator and `dcap.points.public.v1` cache. No production endpoint or effective date is configured for v2.

To inspect the reviewed fictional fixture locally, serve the repository from its root and visit `http://localhost:8765/points/?pointsPreview=synthetic`. The gate accepts only `localhost`, `127.0.0.1`, or `[::1]`, plus that exact query value. Navigation keeps the preview parameter. “Exit local preview” removes it. On the published domain the gate is false.

## Architecture

- `js/points/v2/engine.js` contains the accepted rule inventory and canonical serializer needed by validation. Private scoring and provenance code is excluded.
- `js/points/v2/feed.js` retains the accepted Stage 2C semantic validator, rule definitions, aggregate derivation, ID and hash checks. Its private feed generator is excluded.
- `js/points/v2/validation.js` precomputes SHA-256 with WebCrypto, then supplies synchronous results to the accepted semantic validator. Unexpected hash requests fail. The original v1 validator is unchanged.
- `js/points/v2/cache.js` owns the distinct `dcap.points.public.v2.preview.dev.1` namespace, bounded fixture loading, 60-second freshness, 15-second timeout, abort, validation before caching, and validated last-known-good fallback. Receipt time never represents source modification time.
- `js/points/v2/page.js` renders all seven Points pages and their recent-history surface from one validated revision. It uses text nodes and opaque public IDs for links. Pending summaries never become numerical awards. The Rewards preview makes no entitlement calculation.
- `tests/fixtures/schema-v2-synthetic.json` is the reviewed fictional 25-source-record fixture. `docs/schema-v2.schema.json` records the exact DEV JSON Schema. Neither the private historical preview nor identity evidence is included.

The DEV contract deliberately requires `publication.status=INACTIVE_PRIVATE_DEV`, `previewOnly=true`, `complete=false`, and null production activation fields. Those checks have not been relaxed. The preview shows candidate subtotals and partial rankings only. Recorded cycles are labelled historical; none is identified as current.

## Verification

`npm test` discovers both `.js` and `.mjs` tests: **18 passed, 0 failed, 0 skipped**. The reviewed fixture regenerated byte-for-byte and passed the supplied schema and semantic validator. Tests cover version/field/privacy failures, invalid dates and hashes, IDs and references, aggregate reconciliation, competition ties, rules, preview gating, cache isolation, expiry, corruption, HTTP, network, malformed and oversized response, storage failure, and late timeout response. The six existing v1 tests pass.

Local Chromium checks covered every Points page in synthetic v2 mode at 320, 390, 768, 1024 and 1440 px, with no document overflow. All seven pages passed at 200% text size with semantic table captions and column headers. Keyboard Enter and Space activated the profile Show more/Show less control and updated `aria-expanded`. Fictional profile histories of 0, 1, 5, 6, 10 and 12 entries passed the five/ten limit. An 80-character fictional name fit at 320 px. Invalid fixture, expired validated cache fallback, unknown profile ID, and JavaScript-disabled states passed. Seven v1 pages rendered using the v1 fixture, with no v2 preview banner. These checks ran against a local server; no public preview was deployed.

## Production integration handoff

1. Resolve the remaining historical and committee decisions, including proposed ineligible, ambiguous, Other Commander, source-evidence, event mapping, Student/LT and non-stacking eligibility cases. Refresh the source snapshot at cutover. No frontend code may decide these cases.
2. Reconcile all historical and late contributions. Confirm every new public member ID independently and preserve the observed opaque profile IDs. Do not derive routes from names or invent IDs for missing states.
3. Review a **new production contract and endpoint** with explicit completeness, publication, source freshness, effective/current-cycle and migration-revision semantics. The DEV contract cannot be activated as production. Configure the future endpoint only after feed and client compatibility is verified. Use a new production cache namespace distinct from both existing keys.
4. Verify all pages consume one immutable validated production revision. Test current and historical cycles, complete totals, numerical/pending separation, stable routes, freshness, fallback, and cross-version cache behavior. Rehearse backup and rollback of feed, client, data and cache.
5. Review the secondary Version 4 deployment transition and production trigger/deployment inventory. Obtain explicit final production approval for the exact artifacts and publication window. Switch only through that separately authorized process; retain v1 for rollback.

This branch does not execute any of those production steps. Its synthetic one-member fixture verifies contract handling and UI mechanics; final multi-member identity and historical reconciliation checks remain production gates.
